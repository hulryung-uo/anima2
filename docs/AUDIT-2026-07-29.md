# Multi-team audit — 2026-07-29

Six review teams (architecture, roadmap, process, tests, economy, devil's-advocate) were
run against this repo, their top proposals adversarially verified (three were refuted or
corrected — including one fabricated roadmap citation the verify pass caught), then
synthesized. The devil's-advocate team was lost to an infrastructure error; the synthesis
rests on the other five. This document records the FINDINGS; none of the proposals below
are decisions until acted on.

## Verdict

Micro-level engineering is genuinely strong: differential live gates with honest verdicts
(losses and retractions reported as-is), provenance-wiped economics, a fail-closed
capability authority boundary, 1327 tests in under 4 seconds. What is not going well is
structural: the project keeps paying for ONE defect class — a single world-fact defined in
two places (decide rule vs capability gate; runner N vs runner N+1) synchronized only by
memory. Six live failures trace to it, and **the audit found a seventh, latent today**:
`mage_life.py`'s `fetch_gold` rule ignores the `PICKUP_RADIUS` and pack-cap its gate
enforces (the carpenter's fix was never back-ported). Meanwhile the flagship "Lives" run
on scripted cognition (`_LifeClient` echoes `decide_mode`'s choice as fake LLM JSON) with
no Phase-6 persistence wired in — so the AI-native showcase is currently a hand-written
FSM village whose live hours accumulate no society state — and both deployed craft loops
destroy value at vendor prices (throne −33g; dagger batch −25g once staged iron runs out;
an Ettin pays ~157g vs +10g for the best craft trip).

## Top risks

1. **The dominant failure class does not converge under the current process** — six
   incidents fixed one at a time; the seventh (mage fetch_gold) already exists.
2. **Lives bypass the LLM brain and Phase-6 persistence** — the differentiators sit idle
   while deterministic rules do everything.
3. **Craft loops are value-destroying by construction** — a society scaled on them decays
   to bankruptcy, and gold-per-life fitness would rank crafters below doing nothing.
4. **Resumability contract broken** — CLAUDE.md's "Next:" (~90 commits stale) contradicts
   AUTONOMY-ROADMAP.md §E; this session's live proofs live in uncommitted scratchpad
   scripts.
5. **Scaling cliff at ~3–4 concurrent agents** — hand-tuned pump budgets, insertion-order
   capability priority, string-key contracts across two memories per agent.

## Post-implementation health check (2026-07-30)

A four-team verification workflow + one live run, after all eight proposals landed.
Static layer: fully green (suite, imports, CLI, invariants held structurally, docs
verbatim-checked). Live: a fresh supply-pair run completed its handover cleanly with
zero warnings. The forensics team's raw verdict of "broken" over-read several
deliberately-killed runs as silent deaths, but four of its findings are real:

1. **Harvest relocation never fires in the forge runner** — Grimm has no
   nodes/spot-pool wired, so a drained vein ends the economy (forge2's dead run,
   forge3's zero-reward tail). Fix: wire a spot pool like foundry/eval.py's.
2. **Steering has no ledger role** — consults log as 'chatter'; add a 'steering' role
   so the flagship feature leaves an auditable trace.
3. **The persistence insight was heuristic-authored** — corrected above.
4. **Pipeline monitor starvation — ROOT-CAUSED and fixed.** Not GIL, not process
   priority: the steering-evidence block had been inserted one indent level too
   shallow, which silently moved every status print OUT of the while loop — the loop
   ran (and slept) for four hours printing nothing, then the dedented prints ran once
   at exit. The "5x tick slowdown" claim dissolves with it (it compared a full run's
   duration against another run's observed sample window). Fixes: correct indentation
   with a load-bearing comment; the loop now prints FIRST and sleeps after; every
   block carries `[mon#N +gap T+elapsed]` so cadence anomalies are measurable in-log;
   `_ThrottledAgent` yields with a 10ms scheduling pause instead of a GIL-hot spin;
   worker status lines carry a tick counter.

Also worth adopting from the same report: a liveness line for NON-Life agents (the
forge miner died silently — `out+0.0 steps=0` for 72 samples with nothing flagging
it), and noting that stale finished-goals (want=None with an admitted goal lingering)
are a distinct shape the disagreement detector deliberately does not cover.


## The natural-deposit campaign (2026-07-30, commit a1b0609)

The request "run the forge pair until banking happens NATURALLY" turned into a
five-defect excavation — and a correction to finding #1 above. The full narrative
lives in a1b0609's commit message; the record here keeps the audit honest:

- **Finding #1's diagnosis was wrong twice.** "No spot pool wired" was not the
  hole: relocation IS inherited through the forge chain. The real blockers were
  (a) **tool exhaustion** — both staged pickaxes wore out (ServUO Pickaxe = 50
  uses) and a toolless harvester makes no swings, so the relocation window can
  never fill (forge4: GM-adding one pick revived the miner instantly, 30.3 ->
  122.3); and (b) **window dilution** — a live probe watched invalid-target
  replies ("You can't mine that", ~half the trade spot's probe ring) count as
  "not stuck", so a fully dead bank rated ~0.5 and needed 142 ticks to confess.
  Relocation sampling is now outcome-only (probe verdict: fires at t=48), tools
  scale with the budget and confess when gone, and completed relocations re-home
  the delivery return spot.
- **The bank starvation was a RULE property, not an FSM bug** (the forced-state
  gate had already exonerated the FSM): the patient bank branch below craft only
  fires in a supply gap. A pockets-full band (reserve + one restock) now makes
  banking urgent above 157g — concordance-pinned on both edges.
- **The review pass earned its cost**: five confirmed defects fixed before any
  live budget was spent, including the bank_reserve raw-vs-clamped read that
  recreated the rule-vs-gate drift class through the tuning knob itself.
- **forge8, everything landed**: four sales to 140g, a genuine supply gap, and
  the patient branch deposited **58g on its own** — bank(stage=settle), pack
  settling at exactly the 82g reserve, followed unprompted by a 75g iron
  restock and the next craft batch. Deposit -> working capital -> reinvestment,
  provenance-clean. The forge1 "admitted bank_gold that did not progress"
  anomaly did not recur.
- **Infra footnote**: 1123 auto-created accounts finally crossed ServUO's
  AccountsPerIp=999 — every fresh-account run had begun rolling dice on login
  (forge7's "sell wedge" day and two aborted launches trace here). Raised to
  99999; the restart also reset the runtime ore banks.

**Addendum (same day, commits `f0b7a9~..`)**: the relocation window stayed empty in
the RUNNER even after the sampler fixes — the final thief was `_run_worker` itself,
which called `body.observe()` after every tick for its status pulse. `new_journal`
is since-last-observe: a second consumer on one body steals the batch, so every
journal-borne signal (relocation verdicts, tool-gone clilocs) silently vanished for
every PLAIN agent in every pair runner since the runner was written — the Lives were
immune only because `_CachingBody` exists for exactly this. The worker now reads the
tick's own `_last_observation` (pinned: 5 ticks = exactly 5 observes). forge11
live-proof: `win=7/8 -> 13/16 -> 18/21` filling in the runner for the first time,
then a relocation CHAIN (2611,474 -> 2610,484 -> 2606,499) walking off the drained
mountain autonomously. The lesson joins the mis-indented monitor and the `_why`
wipe: telemetry that touches shared state is not free — and the bug was never in
the skill, but in the harness watching the skill.

**Terrain + lifecycle addendum (commits `d09a636`, `dd5a0e5`)**: two more root causes
behind the same "the economy stops and nothing says why" surface.

1. **Relocation was terrain-blind.** The machinery worked (forge11: window fills,
   fires, chains) but walked a blind compass — forge12 burned a six-spot pool in
   minutes, half of it on the mountain's WRONG FLANK. `uomap.py` now reads the UOP
   land map (ported from v1) and `find_mine_spots()` surveys stand tiles beside real
   rock, one per 8x8 HarvestBank cell, path-filtered by BFS over walkable land. It
   rediscovered the hand-calibrated Phase-3 trade stand from map data alone.
   Relocation consumes the survey as an ITINERARY (nodes installed on arrival,
   within one tile — the last step beside a wall is where greedy walking deflects).
   forge13 live: home vein died -> pool #1 -> fresh bank -> died -> pool #2, each
   hop landing exactly on the surveyed stand.
2. **`bank_gold`'s forge1 anomaly, finally root-caused** — and it was never the FSM
   (the forced-state gate that exonerated it was right). A capability run that ENDS
   without achieving (the FSM gives up and walks home) marked its goal id finished,
   after which every step no-opped while `CapabilityGoalComplete` refused to close an
   unachieved frame: the goal sat admitted until its deadline. An offline
   Life-over-MockBody repro made it deterministic in one afternoon — the complement
   to "force the state under test": **forced-state gates find FSM bugs, offline
   repros find LIFECYCLE bugs**. Wrappers now leave a neutral run-finished marker and
   the frame closes as FAILURE; a transient giveup costs one trip, not the day.

forge14 (everything landed): survey -> two pool relocations -> four sales -> **93g
deposited at 175g, pack settling at exactly the 82g reserve** -> 75g iron restock ->
next batch crafted and sold. Net +135g. Honest scope note: that deposit had iron=3
(below a craft batch), so the urgent band and the patient branch would both have
fired — the urgent band's exclusive trigger remains offline-pinned, not live-proven.
