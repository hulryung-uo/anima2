# Multi-team audit — 2026-07-29

Six review teams (architecture, roadmap, process, tests, economy, devil's-advocate) were
run against this repo, their top proposals adversarially verified (three were refuted or
corrected — including one fabricated roadmap citation the verify pass caught), then
synthesized. The devil's-advocate team was lost to an infrastructure error; the synthesis
rests on the other five. This document records the FINDINGS; none of the proposals below
are decisions until acted on.

## Verdict

Micro-level engineering is genuinely strong: differential live gates with honest verdicts
(losses and retractions reported as-is), provenance-wiped economics, a fail-closed
capability authority boundary, 1327 tests in under 4 seconds. What is not going well is
structural: the project keeps paying for ONE defect class — a single world-fact defined in
two places (decide rule vs capability gate; runner N vs runner N+1) synchronized only by
memory. Six live failures trace to it, and **the audit found a seventh, latent today**:
`mage_life.py`'s `fetch_gold` rule ignores the `PICKUP_RADIUS` and pack-cap its gate
enforces (the carpenter's fix was never back-ported). Meanwhile the flagship "Lives" run
on scripted cognition (`_LifeClient` echoes `decide_mode`'s choice as fake LLM JSON) with
no Phase-6 persistence wired in — so the AI-native showcase is currently a hand-written
FSM village whose live hours accumulate no society state — and both deployed craft loops
destroy value at vendor prices (throne −33g; dagger batch −25g once staged iron runs out;
an Ettin pays ~157g vs +10g for the best craft trip).

## Top risks

1. **The dominant failure class does not converge under the current process** — six
   incidents fixed one at a time; the seventh (mage fetch_gold) already exists.
2. **Lives bypass the LLM brain and Phase-6 persistence** — the differentiators sit idle
   while deterministic rules do everything.
3. **Craft loops are value-destroying by construction** — a society scaled on them decays
   to bankruptcy, and gold-per-life fitness would rank crafters below doing nothing.
4. **Resumability contract broken** — CLAUDE.md's "Next:" (~90 commits stale) contradicts
   AUTONOMY-ROADMAP.md §E; this session's live proofs live in uncommitted scratchpad
   scripts.
5. **Scaling cliff at ~3–4 concurrent agents** — hand-tuned pump budgets, insertion-order
   capability priority, string-key contracts across two memories per agent.

## Implementation record (2026-07-29/30)

All eight proposals were implemented in order, each with its own commit and evidence:

1. **Concordance suite** — failed on the latent mage drift on its first run, exactly as
   predicted; fixed (`FETCH_GOLD_PACK_CAP` single-sourced). Later caught a genuinely
   dead `bank_gold` branch in the brand-new TinkerLife BEFORE its first live run.
2. **Runtime detector** — `WarriorLife.rule_gate_disagreement`, inherited by all
   Lives; no-goal guard pinned against mid-transaction false fires; stayed silent
   through a healthy live smoke (zero false alarms) — the other half of correctness.
3. **LifeRunner harness** — village.py runners de-duplicated (~230 lines removed);
   `LifeSpec` makes omission a TypeError. Live smoke: the harnessed carpenter repeated
   its full buy->craft->sell cycle identically to the pre-refactor runner.
4. **Roadmaps reconciled** — CLAUDE.md is an 83-line entry point; §E quoted verbatim;
   the 37KB narrative moved verbatim to docs/HISTORY.md; DESIGN.md §10 carries the
   autonomy thread and the economically-frozen note.
5. **Thresholds → constructor knobs** — `bank_reserve`/`econ_grace` params;
   `tick()` hands decide the econ agent's OWN memory, so the old drift avenue is
   structurally impossible; fixed the warrior's and mage's latent
   threshold-vs-reserve conflations (reserves now derived: 376g re-arm kit / 180g =
   the fetch cap).
6. **Economy committed** — price-table tripwire (keyed by GRAPHIC after its own first
   draft false-fired on a multi-art entry); net g/h meter; **TinkerLife + fetch_iron +
   the forge pair**: live, both agents provenance-broke, the chain ran
   deliver->fetch->craft->sell to **+140g at ~+2000g/h** — against the frozen
   carpenter chain's −33g/throne. The one anomaly — an admitted `bank_gold` goal that
   did not progress in that first run — was closed by a dedicated forced-state gate
   (`live_tinker_bank_gate.py`): the same Life, spots, NPCs and 140g deposited
   flawlessly in 12 ticks (popup→settle→deposit, pack settling at exactly the 82g
   reserve), so the FSM is exonerated and the wedge stands as a single unreproduced
   mid-run state interaction — with the bank-FSM stage telemetry now resident in the
   pair runner to self-diagnose any recurrence.
7. **Mock item physics + the two-Life sim** — PickUp/Drop/Equip with conservation;
   the REAL WoodsmanLife delivered to the REAL CarpenterLife entirely offline with
   four per-tick oracles. Equip earned its place honestly: the first Life ever ticked
   over the mock wedged on the axe-equip two-step.
8. **LLM steering + persistence** — BOTH live gates passed. Steering
   (`live_steering_gate.py`, forced two-candidate overlap after the natural-overlap
   run logged zero consults): `['buy_reagent','fetch_gold'] -> fetch_gold (LLM)` and
   the agent admitted exactly that goal — a real model overrode the rule's first
   choice, inside the closed vocabulary. Persistence: run A persisted "chop has paid
   off: +0.9 reward over 9 turns." and run B — a new OS process — resumed it verbatim
   at construction. The audit's identity risk ("a scripted FSM village") is no longer
   factually true.
